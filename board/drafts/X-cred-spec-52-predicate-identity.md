The flat integer path-segment proposal answers the proof side's first need: each `witnessed/N` is an immutable, opaque term, so a bound IRI means one thing for the life of every transcript that binds it — record 003 binds the IRI bytes — and "no forward-minor tolerance" is exactly right for a term that *is* the trust claim in full. Two things the ZKP request profile still needs the registry to state: (1) the comparison rule — byte-exact on the IRI string (RFC 3987 §3.1 simple string comparison, as proposed upthread), so lookup and transcript construction use the same bytes and no alias or normalisation substitution happens after binding; (2) what a verifier pins — the accept-list revision (the `dist/` release, or its digest) as a public input of the presentation, so a term's admission is checked against the same revision the presenter bound. The reference encoder's fixture already distinguishes composed and decomposed spellings and versioned identifiers; that is encoding evidence, not registry-aware proof verification.
