# zkbook/ — the DTG ZK Book as a Spec-Up-T project

The construction records (`../board/cards/*.json`) rendered as a specification draft with
[Spec-Up-T](https://github.com/trustoverip/spec-up-t), the same tool the DTG Credentials Core
Specification renders with. **This is a working draft in the evidence repository, not a task-force
deliverable.** The specification and book’s upstream home is [dtgwg-zkp-spec](https://github.com/trustoverip/dtgwg-zkp-spec), with the [current proposed contribution in PR #8](https://github.com/trustoverip/dtgwg-zkp-spec/pull/8). The [catalogue discussion](https://github.com/trustoverip/dtgwg-zkp-spec/discussions/9) indexes all twelve records. This local rendering is supporting material. Since 2026-09-11 the four editor-written chapters that began life in the spec repository (implementation guide · trust-graph operations · integration · research and book) are mirrored here as authored files, so the book edition and the specification hold the same chapters and test E4 covers them. Requirements and adoption decisions remain with the task force.

## The rule

A rendered section may not say more than its record; a record no more than a runtime has measured; a runtime no
more than an independent run has reproduced. So:

- `spec/constructions.md`, `spec/records.md`, `spec/stacks.md`, `spec/privacy-derived.md` and `spec/terms-definitions/g-*.md` are
  **generated** — never edit them here. Edit the record / request / stack, then `node ../board/tools/board.mjs spec` (or `npm run generate`).
  `spec/primer.md` is generated by `tools/transfer-spellbook.mjs` from the hand-kept map in `transfer/`.
- `spec/header.md`, `intro.md`, `terms-and-definitions-intro.md`, `implementation-guide.md`, `trust-graph.md`, `public-inputs.md`,
  `considerations.md`, `conformance.md`, `references.md`, `integration.md`, `research-and-book.md`, `appendix.md` are
  hand-written chapters, authored on both sides: an edit in the spec clone is taken back with `node ../tools/zkbook-export.mjs --adopt`.

## Render

```
cd zkbook
npm install            # spec-up-t ^1.9.0 (pulls its toolchain; ~1 min)
npm run generate       # records → constructions.md + g-*.md terms
npm run render         # → docs/index.html
```

`docs/` is the render output. Spec-Up-T also offers `npm run edit` (watch mode) and `npm run topdf`.

## Promotion path — the split (2026-09-05)

**Specification content → `trustoverip/dtgwg-zkp-spec`** (the Spec-Up-T repository set up on 2026-09-02 by Geoff Turk
and Ry Jones; Pages live at trustoverip.github.io/dtgwg-zkp-spec). `node tools/zkbook-export.mjs` writes the
specification into a clone of that repository in its skeleton (the ten chapter files `specs.json` orders there, `body.md` woven
from records · public-inputs · constructions · stacks · considerations · conformance · references, the background from `primer.md`), with
the validation system as `conformance/` and a CI workflow; `--check` reports what would change without writing.
**Task-force comments, requirements, drafting rules, the board and the discussions stay in `trustoverip/dtgwg-zkp-tf`**;
runtimes, fixtures, the registry and this generator stay here.

Register: the specification text uses plain words — construction record, witness, public inputs, disclosure set,
conformance fixtures, proving system — and no metaphor; a test refuses kitchen vocabulary and emoji headings in
generated spec text. Since 2026-09-16 the JSON records use the same terms as field names (`statement`, `witness`, `publicInputs`,
`relation`, `disclosureSet`, `fixtures`, `options`; state `specified`), so the published `conformance/` files carry no metaphor either. Commits ride the rite; see `COMMIT-PLAN.md`.
