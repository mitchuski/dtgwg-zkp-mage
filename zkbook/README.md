# zkbook/ — the DTG ZK Book as a Spec-Up-T project

The board's cards (`../board/cards/*.json`) rendered as a specification draft with
[Spec-Up-T](https://github.com/trustoverip/spec-up-t), the same tool the DTG Credentials Core
Specification renders with. **This is a working draft in the evidence repository, not a task-force
deliverable.** The specification and book’s upstream home is [dtgwg-zkp-spec](https://github.com/trustoverip/dtgwg-zkp-spec), with the [current proposed contribution in PR #8](https://github.com/trustoverip/dtgwg-zkp-spec/pull/8). The [catalogue discussion](https://github.com/trustoverip/dtgwg-zkp-spec/discussions/9) indexes all twelve records. This local rendering is supporting material: some editor-authored guide and integration chapters live only in the spec repository. Requirements and adoption decisions remain with the task force.

## The rule

A recipe may not say more than its card; a card no more than a runtime has measured; a runtime no
more than an independent run has reproduced. So:

- `spec/recipes.md` and `spec/terms-definitions/g-*.md` are **generated** — never edit them here.
  Edit the card, then `node ../board/tools/board.mjs spec` (or `npm run generate`).
- `spec/header.md`, `spec/intro.md`, `spec/pantry.md`, `spec/terms-and-definitions-intro.md`,
  `spec/appendix.md` are hand-written chapters.

## Render

```
cd zkbook
npm install            # spec-up-t ^1.9.0 (pulls its toolchain; ~1 min)
npm run generate       # cards → recipes.md + g-*.md terms
npm run render         # → docs/index.html
```

`docs/` is the render output. Spec-Up-T also offers `npm run edit` (watch mode) and `npm run topdf`.

## Layout

```
zkbook/
  specs.json                     Spec-Up-T config (markdown_paths order = chapter order)
  package.json                   spec-up-t dependency + scripts
  spec/
    header.md                    title, status, editors, abstract, IPR
    intro.md                     why a book of recipes; what a recipe is; the state machine; how to propose one
    records.md                   GENERATED from board/records/*.json — the requests in the requester's own form;
                                 ADR-001 (Glenn Gore) first, with a clause-by-clause crosswalk into recipe 010
    primer.md                    GENERATED by tools/transfer-spellbook.mjs — how the proofs work, adapted from the
                                 Zero Knowledge Spellbook's Technical Bridges only (narrative excluded by rule);
                                 map + raw bridges + report in transfer/
    pantry.md                    shared public-input conventions (context descriptor, set roots, epoch,
                                 transcript digest, declared scope, public-signal order)
    terms-and-definitions-intro.md
    terms-definitions/           g-*.md generated (gadgets, roles, recipe parts); hand-written terms may sit beside them
    recipes.md                   GENERATED — one section per card, indexed primitive / composed
    appendix.md                  production note, acknowledgements, changelog
```

## Promotion path — the split (2026-09-05)

**Specification content → `trustoverip/dtgwg-zkp-spec`** (the Spec-Up-T repository set up on 2026-09-02 by Geoff Turk
and Ry Jones; Pages live at trustoverip.github.io/dtgwg-zkp-spec). `node tools/zkbook-export.mjs` writes the
specification into a clone of that repository in its own skeleton (header · intro · terms intro · body · appendix), with
the validation system as `conformance/` and a CI workflow; `--check` reports what would change without writing.
**Task-force comments, requirements, drafting rules, the board and the discussions stay in `trustoverip/dtgwg-zkp-tf`**;
runtimes, fixtures, the registry and this generator stay here.

Register: the specification text uses plain words — construction record, witness, public inputs, disclosure set,
conformance fixtures, proving system — and no metaphor; a test refuses kitchen vocabulary and emoji headings in
generated spec text. The card fields (`dish`, `ingredients`, `pantry`, `tasting`) remain the internal names in the
JSON. Commits ride the rite; see `COMMIT-PLAN.md`.
